# دستور مشروع LinguaChat (PROJECT_CONSTITUTION.md)

هذا الدستور هو المرجع القانوني والتنظيمي الأعلى لمشروع **LinguaChat**. جميع أعضاء الفريق ملزمون بقراءة هذا الميثاق والامتثال الكامل لجميع بنوده دون استثناء.

---

## 1. المبادئ العشرة الحاكمة (The Ten Core Principles)

1. **المشروع الواحد غير القابل للتجزئة**: مشروع LinguaChat هو مشروع جماعي موحد ذو كود مصدري مشترك. يمنع منعاً باتاً تحويله إلى مشاريع منفصلة أو جزر منعزلة.
2. **قدسية العقود وتجميدها**: العقود الموجودة في `contracts/` و `docs/` مجمدة تماماً. لا يحق لأي عضو تغيير اسم مسار (Endpoint)، أو اسم حقل JSON، أو اسم جدول، أو نوع رسالة WebSocket.
3. **احترام حدود الملكية (Strict Ownership)**: يمنع منعاً باتاً تعديل ملفات تقع خارج نطاق مسؤوليتك المحددة في [PROJECT_ROLES.md](file:///d:/FOR/A/kadm/aa/linguachat/team_package/docs/PROJECT_ROLES.md).
4. **منع إضافة الحزم دون ترخيص**: يمنع تثبيت أي Package أو Dependency جديد في `package.json` أو `requirements.txt` دون موافقة خطية صريحة من قائد المشروع أحمد العماري.
5. **الأمان الصارم ومنع تسريب الأسرار**: يمنع منعاً باتاً كتابة أي مفتاح سري، أو كلمة مرور، أو API Key، أو JWT داخل الكود المصدري أو ملفات الاختبار. تستخدم المتغيرات البيئية `.env` حصراً.
6. **دورة التطوير الإلزامية (The Standard Loop)**:
   `READ → PLAN → IMPLEMENT → TEST → REVIEW → FIX → TEST → HANDOFF → STOP`.
7. **التوقف الفوري عند التعارض (Stop on Conflict)**: عند اكتشاف أي غموض أو تعارض بين الكود والعقود، يجب التوقف فوراً وعدم ابتداع حلول فردية (Workarounds)، وإبلاغ قائد المشروع.
8. **الدمج المشروط بالنجاح الكامل (No Merge Without PASS)**: لا يتم دمج أي كود في الفرع الرئيسي قبل اجتياز كافة اختبارات الوحدة والتكامل بنسبة 100% واجتياز مراجعة القائد.
9. **حماية النظام من الانحدار (Zero Regression Policy)**: أي تسليم يتسبب في كسر ميزة سابقة أو فشل اختبار موجود مسبقاً يتم رفضه فوراً وإعادته للعضو لإصلاحه.
10. **حزمة `team_package/` للقراءة فقط**: لا يجوز لأي عضو إنشاء أو تعديل أي ملف كود داخل `team_package/`.

## 2. مصفوفة المحظورات القطعية (The 20 Cardinal Sins)

1. تغيير المعمارية الأساسية للنظام.
2. تعديل أي جزء من عقود الـ API Contract.
3. تعديل أي جزء من عقود الـ WebSocket Contract.
4. تعديل أي جزء من عقود الـ Database Schema.
5. تعديل أي جزء من عقود الـ Translation Contract.
6. تعديل أي جزء من عقود الـ Security Contract.
7. إضافة مكتبات أو حزم خارجية جديدة دون موافقة القائد.
8. تعديل ملفات مخصصة لعضو آخر.
9. تنفيذ وظيفة أو ميزة مخصصة لعضو آخر.
10. حذف أو إعادة تسمية ملفات مشتركة.
11. إنشاء Endpoint جديد غير موجود في العقد.
12. إنشاء نوع رسالة WebSocket جديد غير الأنواع الستة المعتمدة.
13. تغيير أسماء الحقول أو أنواع البيانات في الـ Request / Response.
14. تعديل أسماء الجداول أو الأعمدة في قاعدة البيانات.
15. كتابة كلمات مرور أو مفاتيح API داخل الكود.
16. نسخ هيكل المشروع كاملاً داخل مجلد فرعي.
17. إخفاء الأخطاء عبر كتل `try...except pass` فارغة.
18. استخدام القيمة `"none"` في حقل `source_used` للترجمة.
19. الانتقال لمهمة جديدة قبل اعتماد المهمة السابقة واجتياز اختباراتها.
20. دمج الكود دون تقرير تسليم رسمي معتمد.
