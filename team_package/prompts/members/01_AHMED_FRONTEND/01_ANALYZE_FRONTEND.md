# 01 - تحليل متطلبات الواجهات الأمامية والعقود (01_ANALYZE_FRONTEND)

## الهدف
تحليل وتدقيق متطلبات واجهات المستخدم في مشروع LinguaChat، وقراءة العقود الرسمية وتحديد بنية المكونات والصفحات المطلوبة قبل البدء بالتنفيذ.

## اقرأ أولًا
- `team_package/contracts/API_CONTRACT.md`
- `team_package/contracts/WEBSOCKET_CONTRACT.md`
- `team_package/docs/SYSTEM_ARCHITECTURE.md`
- `team_package/prompts/shared/UI_UX_SYSTEM.md`
- `frontend/src/` (فحص الملفات الحالية)

## الملفات المسموح تعديلها
- لا تعدل أي ملفات برمجية في مرحلة التحليل؛ هذه مرحلة قراءة وتخطيط.

## الملفات الممنوع تعديلها
- `backend/**`
- `team_package/**`
- `docs/**`

## المتطلبات الوظيفية
1. فهم صفحات التطبيق الأربعة:
   - صفحة المصادقة وتسجيل الدخول `LoginPage.jsx`.
   - صفحة إدارة واستعراض الغرف `RoomsPage.jsx`.
   - صفحة المحادثة الفورية متعددة اللغات `ChatPage.jsx`.
   - صفحة لوحة التحكم ومؤشرات النظام `DashboardPage.jsx`.
2. فهم تدفق JWT وتخزينه في `localStorage`.
3. فهم متطلبات عميل الـ WebSocket وإعادة الاتصال والـ Heartbeat.

## المتطلبات غير الوظيفية
- التوافق التام مع عقود الـ REST والـ WebSocket.
- اعتماد نظام تصميم عصري يمنح تجربة مستخدم مبهرة.

## Edge Cases
- عدم وجود اتصال بالخادم عند فتح الواجهة.
- التعامل مع التوكن المنتهي الصلاحية أثناء التصفح.

## خطوات التنفيذ
1. قراءة وفحص ملفات `frontend/src/` القائمة.
2. مطابقة مسارات الـ API في الواجهة مع `contracts/API_CONTRACT.md`.
3. مطابقة أنواع رسائل الـ WebSocket مع `contracts/WEBSOCKET_CONTRACT.md`.
4. إعداد خطة المكونات والخطافات (Custom Hooks).

## التحقق
- التأكد من وضوح كافة المتطلبات وعدم وجود أي لبس في العقود.

## الاختبارات
- مراجعة نظرية وتأكيد الجاهزية للبدء بالمرحلة 02.

## معايير النجاح
- إلمام كامل بهيكل الواجهة والعقود وتحديد نقاط التكامل.

## شروط التوقف
- التوقف فوراً إذا وُجد أي تعارض بين الواجهة وعقود الـ Backend.

## ممنوعات المهمة
- ممنوع كتابة أي منطق للـ Backend.
- ممنوع تغيير مسارات الـ API في العقد.

## التسليم
- توثيق نتائج التحليل والاستعداد للمرحلة التالية `02_FRONTEND_FOUNDATION.md`.
