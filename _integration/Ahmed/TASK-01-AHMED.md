# تهيئة بيئة الواجهات ونظام التصميم وعميل الـ API (Frontend Foundation & Client)

## 1. معلومات المهمة

- **رقم المهمة**: `TASK-01-AHMED`
- **العضو المسؤول**: أحمد العماري
- **الدور**: قائد الفريق + مهندس الواجهات الأمامية
- **الحالة**: جاهزة للتنفيذ (Ready to Start)
- **الأولوية**: حرجة (Critical - Foundation)

## 2. هدف المهمة

تهيئة البنية الأساسية لتطبيق الواجهات الأمامية (React/Vite):
1. مراجعة العقود الرسمية وتأكيد جاهزية بيئة العمل لجميع أعضاء الفريق.
2. بناء نظام تصميم مرئي متقدم وعصري (CSS Design System) في `frontend/src/index.css` يدعم التنسيقات المتجاوبة والتدرجات اللونية والانتقالات الناعمة ودعم الاتجاهين (LTR/RTL).
3. بناء عميل الـ API المركزي الموحد في `frontend/src/api/client.js` مع إدارة تلقائية لترويسة المصادقة `Authorization: Bearer <token>` ومعالجة الأخطاء المعيارية.

## 3. لماذا هذه المهمة؟

توحيد لغة التصميم وتوفير عميل HTTP موثوق يربط كل صفحات الواجهة بخوادم الـ REST API بطريقة معيارية تمنع التكرار وتسهل التعامل مع الأخطاء.

## 8. المتطلبات الوظيفية

1. **نظام التصميم (`index.css`)**:
   - تعريف لوحة ألوان احترافية (CSS Custom Properties / Variables): ألوان أساسية، ألوان خلفيات حديثة، تباين عالي للنصوص.
   - خطوط عصرية تدعم اللغتين العربية والإنجليزية بسلاسة.
   - فئات مساعدة (Utility Classes) للكروت الزجاجية (Glassmorphism)، والأزرار التفاعلية، ومؤشرات التحميل (Loading Spinners)، وتنبيهات الأخطاء.
   - دعم كامل للـ Responsive Design (الهواتف المحمولة، الأجهزة اللوحية، الشاشات الكبيرة).
2. **عميل الـ API المركزي (`api/client.js`)**:
   - عنوان الخادم الأساسي: `http://localhost:8000/api/v1` (قابلة للقراءة من `VITE_API_URL` أو قيمة افتراضية).
   - دالة `apiClient(endpoint, options)` أو استخدام Axios/Fetch:
     - حقن تلقائي لرمز التوكن من `localStorage.getItem('linguachat_token')` في ترويسة `Authorization: Bearer <token>`.
     - ضبط `Content-Type: application/json`.
     - معالجة استجابات الأخطاء واستخراج `error.code` و `error.message`.
     - التعامل التلقائي مع خطأ `401 Unauthorized` (تنظيف التوكن والتوجيه لتسجيل الدخول).

## 9. المتطلبات غير الوظيفية

- **التجربة البصرية (Visual Aesthetics)**: تصميم حديث ومبهر يمنح انطباعاً احترافياً فورياً.
- **الأمان**: عدم طباعة التوكن في `console.log` إطلاقاً.

## 10. Edge Cases (الحالات الطرفية)

- انقطاع الاتصال بالخادم (Network Error) -> إرجاع كائن خطأ مفهوم للمستخدم.
- استلام كود 401 لتوكن منتهي أثناء التصفح -> مسح التوكن من `localStorage` وإعادة توجيه سلسة.
- محاولة إرسال Body فارغ أو غير متوافق -> معالجة آمنة للـ JSON serialization.

## 11. خطوات التنفيذ

- **الخطوة 1**: فحص وتحديث `frontend/src/index.css` بنظام ألوان وتنسيقات عصرية.
- **الخطوة 2**: كتابة وتجهيز `frontend/src/api/client.js` لدعم كافة طلبات الـ HTTP (GET, POST, PUT, DELETE).
- **الخطوة 3**: تهيئة المكون الجذري `App.jsx` بالهيكل الأساسي ونظام التنقل.
- **الخطوة 4**: فحص بناء الواجهة عبر `npm run build` أو التحقق من عدم وجود أخطاء في الـ Console.

## 13. الاختبارات المطلوبة

- التحقق من عمل `apiClient` مع طلبات الـ GET والـ POST.
- التحقق من حقن الترويسة `Authorization: Bearer <token>` عند وجود توكن.
- التحقق من التعامل الصحيح مع استجابات الخطأ القياسية.
- تشغيل فحص البناء: التأكد من سلامة كود الـ React.
