# واجهة المحادثة متعددة اللغات وربط الـ WebSocket (Chat UI & Real-Time Hook)

## 1. معلومات المهمة

- **رقم المهمة**: `TASK-04-AHMED`
- **العضو المسؤول**: أحمد العماري
- **الدور**: قائد الفريق + مهندس الواجهات الأمامية
- **الحالة**: جاهزة للتنفيذ بعد TASK-03
- **الأولوية**: حرجة جداً (Critical - Flagship Feature)

## 2. هدف المهمة

بناء وتنفيذ واجهة المحادثة التفاعلية الفورية في `frontend/src/pages/ChatPage.jsx` وتطوير خطاف الويب سوكت `frontend/src/hooks/useWebSocket.js` وخدمة العميل `frontend/src/services/websocket.js`:
1. فتح قناة الاتصال الحي `ws://localhost:8000/ws/{room_id}?token=<jwt>` وإرسال الـ Heartbeat كل 30 ثانية وتطبيق استراتيجية إعادة الاتصال الأسي (Exponential Backoff).
2. استرجاع الرسائل السابقة المترجمة عبر `GET /rooms/{room_id}/messages`.
3. عرض الرسائل الحية مع إبراز: النص المترجم، النص الأصلي، لغة المصدر، ومصدر الترجمة (`translation_source`).
4. معالجة أحداث `JOIN` و `LEAVE` ومؤشر جاري الكتابة `TYPING` ورسائل الأخطاء `ERROR`.

## 3. لماذا هذه المهمة؟

شاشة الدردشة متعددة اللغات هي القيمة الجوهرية والواجهة الرئيسية لمشروع LinguaChat؛ حيث يتواصل المستخدمون من مختلف الثقافات مع ترجمة فورية حية تظهر سلاسة النظام وتكامله.

## 8. المتطلبات الوظيفية

1. **خدمة وخطاف الـ WebSocket (`services/websocket.js`, `hooks/useWebSocket.js`)**:
   - الاتصال بعنوان: `ws://localhost:8000/ws/{room_id}?token=${token}`.
   - مؤقت إرسال نبضات `HEARTBEAT` كل **30 ثانية**:
     ```json
     {"type": "HEARTBEAT", "payload": {}, "timestamp": "...", "room_id": "..."}
     ```
   - استراتيجية إعادة الاتصال التلقائي عند الانقطاع (Exponential Backoff: 1s, 2s, 4s, 8s, max 30s) بحد أقصى 10 محاولات ثم إشعار المستخدم.
   - دوال إرسال:
     - `sendMessage(text, original_language = null)`: إرسال `TEXT_MESSAGE`.
     - `sendTyping(is_typing)`: إرسال حدث `TYPING`.
2. **واجهة المحادثة (`ChatPage.jsx`)**:
   - **الترويسة (Chat Header)**: اسم الغرفة، مؤشر حالة الاتصال المباشر (متصل أخضر / جارٍ إعادة الاتصال أصفر / منقطع أحمر)، وزر العودة لقائمة الغرف.
   - **منطقة الرسائل (Message List)**:
     - التمرير التلقائي لأسفل عند وصول رسائل جديدة.
     - استرجاع الرسائل السابقة عند فتح الغرفة.
     - عرض فقاعة الرسالة (Message Bubble):
       - اسم المرسل وتوقيت الإرسال.
       - تمييز رسائل المستخدم الحالي (يمين/لون مميز) عن رسائل الآخرين (يسار).
       - عرض **النص المترجم** بشكل رئيسي وواضح.
       - إمكانية عرض **النص الأصلي** بنقرة زر أو تحته مباشرة.
       - شارة صغيرة توضح مصدر الترجمة (مثل: "مترجم بواسطة LibreTranslate" أو "نفس اللغة / Identity").
     - عرض أحداث الانضمام والمغادرة كرسائل نظام في المنتصف ("انضم فلان إلى المحادثة").
     - عرض مؤشر "فلان يكتب الآن..." (Typing Indicator).
   - **صندوق الإدخال (Chat Input Box)**:
     - حقل نصي متعدد الأسطر يدعم الضغط على Enter للإرسال و Shift+Enter لسطر جديد.
     - زر إرسال تفاعلي.
     - إرسال حدث Typing عند بدء الكتابة، وإلغاؤه عند التوقف (Debounce 2 ثانية).
     - منع إرسال الرسائل الفارغة أو التي تتجاوز 4096 بايت.

## 9. المتطلبات غير الوظيفية

- **الجمالية والرشاقة (Fluid Aesthetics)**: رسوم متحركة ناعمة لظهور الرسائل ومؤشر الكتابة.
- **التوافق اللغوي**: دعم اتجاه النص التلقائي (RTL للعربية و LTR للإنجليزية) داخل نفس الرسائل.

## 10. Edge Cases (الحالات الطرفية)

- انقطاع الإنترنت فجأة -> إظهار شريط علوي يفيد بمحاولة إعادة الاتصال التلقائي مع العداد.
- فشل الترجمة واستلام النص الأصلي -> تمييز الرسالة وتوضيح أنها بالنص الأصلي.
- إرسال رسالة سريعة قبل اكتمال الاتصال -> تعطيل زر الإرسال أثناء الانقطاع أو الانتظار في طابور.
- تلقي رسالة خطأ `ERROR` من الخادم -> إظهار Toast تنبيهي للمستخدم دون قطع الجلسة.

- **الخطوة 3**: تصميم مكونات `MessageBubble.jsx` و `TypingIndicator.jsx` و `ChatHeader.jsx`.
- **الخطوة 4**: تجميع صفحة `frontend/src/pages/ChatPage.jsx` وجلب السجل التاريخي ودمجه مع الرسائل الحية.
- **الخطوة 5**: اختبار تبادل الرسائل في الوقت الفعلي بين نافذتين مختلفتين بلغات مختلفة.

## 13. الاختبارات المطلوبة

- اختبار الاتصال بالويب سوكت عند دخول الصفحة وإغلاقه عند مغادرتها.
- اختبار إرسال واستقبال رسالة نصية في الوقت الفعلي.
- اختبار إرسال نبضات الـ Heartbeat كل 30 ثانية.
