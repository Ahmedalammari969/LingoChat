11. المشاكل والأخطاء الشائعة وكيفية تصحيحها وحلها فوراً (Ahmed Troubleshooting Guide)

🚨 المشكلة 1: خطأ CORS عند استدعاء الـ API من المتصفح (CORS Policy Block)

السبب: إرسال طلب من localhost:5173 إلى localhost:8000 بدون تفعيل الـ Proxy في Vite.

الحل البرمجي السريع: تأكد أن vite.config.js يحتوي على إعدادات الـ proxy لمسار /api إلى http://localhost:8000، أو استدعِ المسار الكامل المصرح به في الـ Backend.

🚨 المشكلة 2: تكرار الاتصال بالـ WebSocket وتجميد الصفحة (Infinite Reconnection Loop)

السبب: استدعاء دالة الاتصال داخل useEffect بدون مصفوفة تبعيات (Dependency Array) صحيحة.

الحل البرمجي السريع: تأكد أن useEffect يعتمد فقط على [roomId, token] ويحتوي على دالة تنظيف return () => ws.close() لإغلاق الاتصال القديم عند مغادرة الصفحة.

🚨 المشكلة 3: بقاء المستخدم معلقاً عند انتهاء صلاحية الـ JWT (Expired Token Handling)

الحل البرمجي السريع: في ملف src/api/client.js، أضف Interceptor يفحص كود 401 ويقوم فوراً بمسح التوكن من localStorage وإعادة توجيه المستخدم لصفحة /login.

7. الميثاق والدستور الموحد لأعضاء الفريق الأربعة (Unified Team Constitution)

لضمان نجاح دمج المشروع ومنع حدوث أي تعارضات أو أخطاء عند تجميع أعمال الفريق، يلتزم كل عضو بالقواعد الصارمة التالية:

📜 الدستور البرمجي الموحد (The Golden Rules)
  1. عزل الملكية التام (Zero Cross-Editing): ممنوع منعاً باتاً تعديل أي ملف خارج نطاق ملكيتك المحددة. إذا احتجت ميزة من زميلك، استدعِ الدالة المصرح بها ولا تكتب كوده بنفسك.
  2. تجميد العقود الرسمية (Frozen Contracts): لا يحق لأي عضو تغيير أسماء مسارات الـ API أو صيغ رسائل الـ WebSocket أو أسماء حقول قاعدة البيانات دون موافقة كتابية رسمية من قائد المشروع أحمد العماري.
  3. قاعدة الترجمة الحتمية (Identity Rule): يمنع استخدام القيمة "none" نهائياً في أي سياق للترجمة. إذا كانت لغة المصدر هي نفس لغة الهدف، تكون النتيجة دائماً: source_used = "identity" و confidence = 1.0.
  4. حظر الأسرار والـ Hardcoded Keys: ممنوع وضع أي مفتاح سري أو كلمة مرور أو Token داخل ملفات الكود البرمجي؛ كافة الإعدادات تُقرأ من ملف .env حصراً.
  5. قاعدة الـ Stop & Fail: إذا فشل الاختبار في الخطوة 4، لا تنتقل للمهمة التالية أبداً، ولا تخفِ المشكلة، بل أصلح الكود داخل ملفك المخصص حتى يظهر PASSED باللون الأخضر.

8. بروتوكول منع أخطاء التكامل والدمج (Zero-Regression & Merge Policy)

مجال التكامل الالتزام الصارم المطلوب من العضو الخطأ الشائع المحظور قطيعاً
الـ REST API الالتزام بنموذج الاستجابة الموحد data / error وأكواد الحالة (200, 201, 400, 401, 403, 404, 409). تغيير اسم حقل في JSON أو إرجاع كود 200 عند حدوث خطأ.
الـ WebSocket الالتزام بالأنواع الستة فقط (JOIN, LEAVE, TEXT_MESSAGE, TYPING, HEARTBEAT, ERROR) وحجم 4096B. ابتكار نوع رسالة جديد أو تجاوز حد حجم الرسالة المسموح به.
الـ Database استخدام معرفات UUIDv4 لكافة الجداول، وإجراء التعديلات عبر هجرات Alembic حصراً. تعديل الجداول يدوياً في قاعدة البيانات دون كتابة سكريبت Migration.
الـ Frontend حفظ التوكن في localStorage، والتعامل السلس مع حالات التحميل والخطأ وتحديث الواجهة تلقائياً. افتراض استجابة الـ API دائماً دون معالجة حالات الانقطاع أو البطء.
