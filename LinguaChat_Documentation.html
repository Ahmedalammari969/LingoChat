1. الملخص التنفيذي ونطاق المشروع (Executive Summary)

1.1 المشكلة والدافع الهندسي (Problem Statement)

في بيئات التواصل والعمل العالمية متعددة الجنسيات، يمثل اختلاف اللغات حاجزاً رئيساً يعيق التفاعل السلس والفوري بين الفرق والمستخدمين. تتطلب الحلول التقليدية قيام المستخدم بنسخ النصوص ولصقها في أدوات ترجمة خارجية، مما يقطع تدفق المحادثة ويفقد السياق اللحظي. جاء مشروع LinguaChat لتقديم حل تقني متكامل يتيح التواصل في غرف جماعية فورية بحيث يكتب كل مستخدم بلغته الأم (العربية، الإنجليزية، الفرنسية، وغيرها)، وتصل الرسائل لبقية الأعضاء مترجمة فورياً إلى لغاتهم المفضلة في أجزاء من الثانية مع الحفاظ على النص الأصلي.

1.2 الأهداف التقنية للنظام (System Objectives)

⚡ الاتصال الفوري اللحظي (Real-Time)

تبادل الرسائل وأحداث الانضمام والمغادرة ومؤشرات الكتابة والنبضات عبر قنوات WebSocket غير متزامنة ذات زمن استجابة متدنٍ للغاية.

🌐 الترجمة التلقائية الذكية (Smart Translation)

كشف اللغات تلقائياً، والترجمة المتوازية لكل متلقٍّ، وتخزين النتائج في كاش سريع، وتطبيق قاعدة الـ Identity عند تطابق اللغات لتوفير الموارد.

🔒 الأمان والمصادقة الصارمة (Zero-Trust Security)

مصادقة JWT في REST و WebSocket، وتشفير Bcrypt cost 12، وعزل عضوية الغرف، وحظر تسريب الأسرار وحماية النظام من هجمات DoS و XSS.

🏛️ المعمارية النظيفة والعقود المجمدة (Clean Contracts)

فصل تام بين طبقات النظام، وتجميد العقود الرسمية لمنع التضارب بين أعضاء الفريق الأربعة، مع جاهزية كاملة للاختبارات الآلية.

2. المعمارية الهندسية الشاملة للنظام (System Architecture)

2.2 تدفق البيانات اللحظي للرسائل (End-to-End Message Flow)

دورة حياة الرسالة من لحظة كتابتها إلى استلامها مترجمة:
  1. المرسل (Client A): يكتب الرسالة باللغة العربية ("مرحباً بكم") ويضغط إرسال. يقوم خطاف useWebSocket بتغليف الرسالة بنوع TEXT_MESSAGE وحجم أقل من 4096 بايت.
  2. خادم WebSocket: يستقبل الرسالة ويفحص سلامة الـ JSON والحجم، ثم يستدعي messages_service.create_message() لحفظ النص الأصلي في قاعدة البيانات فوراً.
  3. خدمة الترجمة (Parallel Processing): يحدد الخادم لغة كل مستلم متصل بالغرفة (مثلاً: المستلم B لغته الإنجليزية، والمستلم C لغته العربية):
    • بالنسبة للمستلم C (عربي -> عربي): تطبق قاعدة الـ Identity فوراً دون أي استدعاء خارجي وتكون source_used = "identity" و confidence = 1.0.
    • بالنسبة للمستلم B (عربي -> إنجليزي): يفحص الكاش (Cache Hit/Miss)، وفي حال الـ Miss يستدعي محرك LibreTranslate عبر HTTP بمهلة 10 ثوانٍ مع خيار Google Fallback، ثم يخزن النتيجة في الكاش.
  4. الحفظ والتسليم: يتم حفظ الترجمة في جدول translations، وبث الرسالة المترجمة للمستلم B والنص الأصلي للمستلم C في نفس اللحظة.

5.2 بروتوكول الويب سوكت اللحظي (WebSocket Protocol Specification)

📡 نقطة الاتصال وأكواد الإغلاق (Close Codes)

URL: ws://localhost:8000/ws/{room_id}?token=<access_token>

  • 4001: غير مصرح (Unauthorized - توكن مفقود أو غير صالح).
  • 4003: ممنوع (Forbidden - المستخدم ليس عضواً في الغرفة).
  • 4004: الغرفة غير موجودة (Room Not Found).
  • 1000: إغلاق طبيعي عند مغادرة المستخدم.
📦 الغلاف الموحد والأنواع الستة (The 6 Allowed Types)

الغلاف الإلزامي: {"type": "...", "payload": {}, "timestamp": "ISO8601", "room_id": "uuid"}

  • JOIN: بث انضمام مستخدم للغرفة.
  • LEAVE: بث مغادرة أو انقطاع مستخدم.
  • TEXT_MESSAGE: تبادل الرسائل النصية المترجمة (حد 4096 بايت).
  • TYPING: بث مؤشر "يكتب الآن...".
  • HEARTBEAT: نبضة كل 30 ثانية (فصل بعد 90 ثانية صمت).
  • ERROR: إشعار العميل بالأخطاء دون قطع الاتصال.

6. معمارية الترجمة التلقائية والأمان الشامل (Translation & Security)

6.1 قواعد ومحركات الترجمة التلقائية (Translation Architecture)

⚡ قاعدة الـ Identity الإلزامية (The Identity Rule)

عندما تكون لغة المصدر مطابقة للغة الهدف (source_lang == target_lang): يعاد النص الأصلي فوراً مع source_used = "identity" و confidence = 1.0 دون استدعاء أي مزود أو كاش.
حظر قطعي: يمنع منعاً باتاً استخدام القيمة "none" في أي حقل بالنظام.

🗄️ طبقة الكاش ومزودو الخدمة (Providers & Cache)

- مفتاح الكاش: translate:{source}:{target}:{sha256(text)} بمدة صلاحية TTL = 3600s بنمط In-Memory مع دعم Redis Fallback.
- المزود الأساسي: LibreTranslate API مع مهلة زمنية صارمة 10 ثوانٍ.
- المزود الاحتياطي: Google Translate API يعمل اختيارياً عند توفر المفتاح.

6.2 مصفوفة الأمان والمصادقة (Security & Integrity Matrix)

المحور الأمني التقنية والمعايير المعتمدة آلية الحماية والتطبيق
تشفير كلمات المرور passlib[bcrypt] بمعامل كلفة 12 تشفير كلمة المرور قبل الحفظ في DB، وحظر إرجاع hashed_password في أي API.
مصادقة JWT خوارزمية HS256 وصلاحية 60 دقيقة تضمين sub كـ UUID و preferred_language، وتمريره في ترويسة Bearer أو query param.
عزل الصلاحيات فحص عضوية الغرف (Room Authorization) حظر استرجاع الرسائل بكود 403 وإغلاق اتصال الـ WS بكود 4003 لغير الأعضاء.
مكافحة DoS و Injection SQLAlchemy ORM + حد 4096B للرسائل استعلامات معلمة لمنع SQLi، وتقييد حجم رسائل WebSocket بـ 4096 بايت لمنع الإغراق.
إدارة الأسرار (Zero Secrets) قراءة الإعدادات من .env حصراً حظر كامل لكتابة أي API Key أو Secret Key أو Token داخل الكود أو ملفات الاختبار.
